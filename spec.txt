# Books API Week 02 Spec - Version 2

## General Rules (apply to all routes)

### Field Validation
Every `POST` and `PUT` request is validated before touching the database:
- Every required field must be present in the request body.
- Every required field must have the type defined in its data model. Values of any other type (objects, arrays, `null`, booleans, etc.) are rejected.
- String fields are trimmed; an empty string (`""` or only spaces) counts as a missing field.
- `publicationDate` must use the format `YYYY-MM-DD` and be a real date (for example, `2026-02-30` is rejected).
- `birthYear` must be a whole number (for example, `1965`) and cannot be greater than the current year. Strings such as `"1965"` are rejected.
- Only the fields defined in the data model are saved. Any extra field in the request body is ignored.
- The custom `id` of a document cannot be changed. If an `id` is included in a `PUT` body, it is ignored and the `id` from the route parameter is used.

If validation fails, the API responds with `400` and does not modify the database.

### Error Response Format
Every error response uses the same JSON structure:

    {
      "error": "A short message explaining what went wrong"
    }

Error messages must clearly say which field or document caused the problem. Standard messages:

| Status | Situation | Example message |
|--------|-----------|-----------------|
| `400` | Required field missing or empty | `"Missing required field: title"` |
| `400` | Field has the wrong type | `"Field title must be a string"` |
| `400` | Invalid date format | `"publicationDate must use the format YYYY-MM-DD"` |
| `400` | Invalid birth year | `"birthYear must be a whole number not greater than the current year"` |
| `400` | `authorId` does not match an author | `"Author a9 does not exist"` |
| `404` | Book not found | `"Book b9 not found"` |
| `404` | Author not found | `"Author a9 not found"` |
| `409` | Book id already exists | `"A book with id b4 already exists"` |
| `409` | Author id already exists | `"An author with id a1 already exists"` |
| `409` | Author still has books | `"Author a1 cannot be deleted because 2 books still reference it"` |
| `500` | Unexpected server or database error | `"Internal server error"` |

`500` responses must never include stack traces, database error details or connection information.

Successful responses return documents with only the fields defined in the data model (`_id` from MongoDB is not included).

## Feature 1: Book CRUD Operations and Author References

### Goal
Update the existing Week 01 book API so book documents include a reference to an author and the API
supports all CRUD operations for books. Every book route must be documented and testable in Swagger.

### Data Model

Book documents will be stored in the `books` collection.

Required book fields:
- `id`: string, required, custom id such as `b1`
- `authorId`: string, required, references the `id` field of an author document
- `title`: string, required
- `publicationDate`: string, required, format `YYYY-MM-DD`

Books will continue to use custom string ids instead of MongoDB `_id` values for route parameters.

### Relationship to Authors
Each book will identify its author with an `authorId` field. The value of `authorId` must
match the custom `id` value of an existing author document.
When creating or updating a book, the API should reject the request with a `400` status
code if the submitted `authorId` does not match an existing author.

### Routes

#### GET /books
Purpose: Return all books.

Success:
- Status code: `200`
- Response body: an array of book objects

        [
          {
            "id": "b1",
            "authorId": "a1",
            "title": "Example Book Title",
            "publicationDate": "2026-01-15"
          }
        ]

Errors:
- `500` if an unexpected server or database error occurs

#### GET /books/:id
Purpose: Return one book by its custom id.

Success:
- Status code: `200`
- Response body: the matching book object

Errors:
- `404` if no book exists with that id
- `500` if an unexpected server or database error occurs

#### POST /books
Purpose: Create a new book.

Request body:

    {
      "id": "b4",
      "authorId": "a1",
      "title": "Example Book Title",
      "publicationDate": "2026-01-15"
    }

Success:
- Status code: `201`
- Response body: the newly created book object

Errors:
- `400` if a required field is missing, empty or not a string
- `400` if `publicationDate` does not use the format `YYYY-MM-DD`
- `400` if the `authorId` does not match an existing author
- `409` if the `id` already exists
- `500` if an unexpected server or database error occurs

#### PUT /books/:id
Purpose: Update an existing book.

Request body:

    {
      "authorId": "a2",
      "title": "Updated Book Title",
      "publicationDate": "2026-02-20"
    }

Success:
- Status code: `200`
- Response body: the updated book object

Errors:
- `400` if a required field is missing, empty or not a string
- `400` if `publicationDate` does not use the format `YYYY-MM-DD`
- `400` if the `authorId` does not match an existing author
- `404` if no book exists with that id
- `500` if an unexpected server or database error occurs

#### DELETE /books/:id
Purpose: Delete an existing book.

Success:
- Status code: `204`
- Response body: a confirmation that the requested book was eliminated from the database

Errors:
- `404` if no book exists with that id
- `500` if an unexpected server or database error occurs

### Swagger Documentation
Swagger must document every book route.

### Deployment Expectations
After implementation, the book routes must work locally and from the deployed Render application. The deployed Swagger page at `/api-docs` must allow someone to test every book route from the browser.

## Feature 2: Author CRUD Operations

### Goal
Create the `authors` collection and all of its CRUD operations.

### Data Model

Author documents will be stored in the `authors` collection.

Required author fields:
- `id`: string, required, custom id such as `a1`
- `name`: string, required
- `birthYear`: number (whole number), required, such as `1965`

Authors will use custom string ids instead of MongoDB `_id` values for route parameters.

### Relationship to Books
Books reference authors through their `authorId` field, which must match the `id` of an author.
An author cannot be deleted while any book still references its `id`.

### Routes

#### GET /authors
Purpose: Return all authors.

Success:
- Status code: `200`
- Response body: an array of author objects

        [
          {
            "id": "a1",
            "name": "Author's Name",
            "birthYear": 1965
          }
        ]

Errors:
- `500` if an unexpected server or database error occurs

#### GET /authors/:id
Purpose: Return one author by its custom id.

Success:
- Status code: `200`
- Response body: the matching author object

        {
          "id": "a1",
          "name": "Author's Name",
          "birthYear": 1965
        }

Errors:
- `404` if no author exists with that id
- `500` if an unexpected server or database error occurs

#### POST /authors
Purpose: Create a new author.

Request body:

    {
      "id": "a3",
      "name": "Author's Name",
      "birthYear": 1965
    }

Success:
- Status code: `201`
- Response body: the newly created author object

Errors:
- `400` if a required field is missing, empty or has the wrong type
- `400` if `birthYear` is not a whole number or is greater than the current year
- `409` if the `id` already exists
- `500` if an unexpected server or database error occurs

#### PUT /authors/:id
Purpose: Update an existing author.

Request body:

    {
      "name": "Updated Author's Name",
      "birthYear": 1966
    }

Success:
- Status code: `200`
- Response body: the updated author object

Errors:
- `400` if a required field is missing, empty or has the wrong type
- `400` if `birthYear` is not a whole number or is greater than the current year
- `404` if no author exists with that id
- `500` if an unexpected server or database error occurs

#### DELETE /authors/:id
Purpose: Delete an existing author.

Success:
- Status code: `200`
- Response body: a confirmation that the requested author was eliminated from the database

        {
          "message": "Author a1 was deleted"
        }

Errors:
- `404` if no author exists with that id
- `409` if one or more books still reference the author's `id`
- `500` if an unexpected server or database error occurs

### Special Case: Deleting an Author That Still Has Books
If a user tries to delete an author whose `id` is still used as the `authorId` of one or more books,
the deletion is blocked and the author is not removed. The API responds with `409` and a message
explaining the problem and how to solve it:

    {
      "error": "Author a1 cannot be deleted because 2 books still reference it. Delete or reassign those books first."
    }

### Swagger Documentation
Swagger must document every author route, including request bodies, success responses and error responses.

### Deployment Expectations
After implementation, the author routes must work locally and from the deployed Render application.
The deployed Swagger page at `/api-docs` must allow someone to test every author route from the browser.
